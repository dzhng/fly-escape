# Actual body requests invalidate the current certificate route

The isolated body diagnostic captures six real `Body::step` requests before movement acceptance. The caller retains its neural command and world scale. An upright fly turns toward the support normal by about 0.08 radians in the first 20 ms substep, even when requested planar yaw is tiny. Earlier pure-yaw fixtures did not exercise this actual request.

At a five-million projection cap, the three upright requests certify only 0.0019–0.0038% of that substep and take about 26 ms each in a single native run. The three already-aligned starts cannot be represented by the retained triangle-face/hull-vertex chart finder. These are algorithm limitations; neither result establishes physical blockage or support loss. Numeric details, captured commands and source hashes are in [the result](actual-body-request-results.json).

This is a rejected route for immediate consumer adoption. Further formal chart coverage and quaternion error machinery are paused. The 10 nm collision-query classification precision is not a user requirement for whole-motion proof. A practical numerical contact experiment must measure its own movement error against native geometry and maximum close-view pixels, retain one core-generated trajectory for replay, and distinguish work exhaustion from a real blocking contact.

A separate scratch test verifies that the core sampler and its JSON roundtrip preserve the stored initial pose and freeze after the actual partial-tick terminal fraction. That test deliberately uses an unaccepted pinned formula and establishes only numeric transport behavior, not physical movement correctness. No WASM or browser result is claimed.

The runnable scratch owners remain `/tmp/fly-supported-motion` and `/tmp/fly-rotation-probe`; no scratch implementation ships in this checkpoint.
