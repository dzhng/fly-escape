# Shared house renderer checkpoint

The geometry target is an intact five-room footprint, a pantry with one physical opening, a fly visibly crossing that opening, and walls that reveal a followed fly without changing collision. Neutral materials deliberately keep palette and lighting out of this checkpoint.

The asset workbench exposes `?fixture=house` through its “Five-room house” link. Both modular assets map directly to the shared geometry payload. Door probes subtract wall coverage from shared room boundaries; there is no handwritten TypeScript doorway map. Local replacement validates native bounds/pivots, shares resources across placements, and releases the previous parts. A failed or superseded load retains the displayed part.

[Browser verification](../../../../../tests/browser/house.mjs) exercises real controls for overview, pantry, doorway crossing and cutaway, repeats wall/floor replacement, and rejects a floor uploaded as a wall. [Results](browser/report.json) retain equal GPU geometry/texture counts before and after replacement and no browser errors. The existing fly asset workbench browser regression also passes. Renderer tests pin open passages, complete nested-segment cutaway and one-time resource disposal. Disabling recursive ray intersection makes the cutaway test fail, then restoration passes. Typecheck and the asset-lab production build pass. No core or WASM source/build was changed.

[Whole layout](browser/overview.png), [door threshold](browser/pantry-threshold.png), and [wall cutaway](browser/pantry-cutaway.png) provide the main review surfaces; all captured states have matching enlarged crops. [Pixel telemetry](browser/pixels.json) deliberately measures the world separately from UI. The large uniform areas (dominant gray shares around 0.8–0.9) reflect a sparse greybox; overview still contains the complete footprint and all door gaps, while close views place the fly centrally. The prior kit renders show isolated pieces rather than a comparable layout, so no misleading paired image score is claimed.

Adversarial inspection: the pantry-center close view is mostly empty floor and cannot establish room topology by itself; the overview is required. Cutaway at the corner removes both intervening wall segments and can read like an open platform; the overview and physical geometry fixture establish the walls still exist. Fine diagonal shading is visible on wall faces at close scale; final lighting acceptance remains open. The baseline fly ring still sits at floor height during airborne poses; integration must retain the root's aerial selection-ring correction before final shots. Fresh independent review inspected all six full screenshots and all six crops. It confirmed readable five-room topology, intact gaps/joins and no fly intersection at the threshold. It flagged the corner cutaway losing enclosure (high confidence), close views relying on overview/UI for room identity (high), and stepped/diagonal wall-shadow banding (medium). These remain explicit final-acceptance limits; no palette/lighting or partial-wall clipping is introduced in this bounded pass. CLI independent code review also failed at startup: the configured model requires a newer CLI; no review findings were produced.

Shape review centralizes room mesh ownership and deletes the old inline wall builder. Diff review verified local replacement generations and pagehide invalidation, and removed a cross-package private resource import. Documentation keeps the geometry and asset contract in their existing owners. This checkpoint is prepared for integration, not full slice acceptance: the existing Geometry wire contract has no solid-prop footprints. A follow-up core contract and collision fixture must precede solid prop meshes.
