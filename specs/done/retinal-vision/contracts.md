# Contracts inherited by implementation

## Optical profile and scene

The accepted acquisition `EyeProfile` contains capture dimensions 128×128, two eyes, a 721-cell regular hex layout (radius fifteen), RGB8 color samples, one acquisition per 0.1-second tick, and hashes for rig, layout and photometric settings. Sample order is eye L then R; within an eye, axial rows and columns increase in the order frozen by slice 01. Each sample pools its assigned raster pixels, not a guessed number of biological receptors. No sample may be an empty pixel pool; quality selection must catch that before freezing a profile.

Slice 01 derives angular projection from the pinned reference and records the transformation into our coordinate system. The reference uses 157° vertical perspective FOV, a 450×512 source raster and a fisheye transformation; copying those numbers without translating its axes and units is incorrect. Slice 03 locates the rig on our actual fly asset. Eye origins are fixed to the native body frame, in metres. Use full pre-neural position, height and quaternion; do not use walking animation bones, presentation scale, interpolated poses, or heading alone. Head stabilization and articulated eye motion are outside this feature.

Use the existing authored walls, floor, furniture, food, tools and static light fixtures, at resolved setup transforms. Preserve mesh holes and height-dependent visibility. Share source meshes/material inputs and light authoring with the game. A physical window can reveal the exterior; exit scoring metadata cannot manufacture a bright target.

The sensory scene excludes player cutaways, selection rings, trails, field overlays, labels, star effects and screen-space presentation effects. Freeze decorative grass and purely decorative animation out of the sensory scene. Freeze other flies and the observing fly's body out of this first sensor model: this avoids near-plane self-intersection and makes social/self vision an explicit future variable. Do not call it full self-occluding animal vision. Physical placement geometry remains visible; fan blade animation is frozen at an authored phase. This scope is recorded with the scene identity.

Fixed exposure, color space and sample pooling are part of the profile. Start with existing authored base color/emission and shared scene lighting, no auto exposure, temporal AA or camera-dependent tone curve. Decode source colors into linear RGB, pool each channel independently with canonical GPU Float32 sums, and quantize each as `round(255 × clamp(exposure × channel, 0, 1))`. Freeze exposure from neutral and chromatic optical fixtures before neural tests. The RGB8 samples are the canonical input; luminance is only a derived branch. For diagnostic matched-brightness fixtures use the declared `0.2126R + 0.7152G + 0.0722B` linear-RGB metric, and separately verify equality at the actual brightness-adapter output. This metric is not a claim about fly spectral sensitivity. Document shadows, shade-object appearance and excluded effects in the slice-03 scene manifest. Do not secretly multiply samples by the old directional brightness field. The aim is an explicit low-cost optical model, not calibrated photometry.

A request identifies attempt, client generation, tick, profile/scene identities and ordered active fly IDs. Each `EyePose` carries the full beginning-of-tick native body transform. A batch repeats request identity and carries exactly `activeFlyCount × 2 × sampleCount × 3` bytes. All eyes see the same frozen beginning-of-tick world. Dead/escaped/otherwise terminal flies do not request new input.

## Tick transaction and failure behavior

There is at most **one pending acquisition batch per attempt**. `prepare_tick` neither advances fields nor brains/bodies. `commit_tick` rejects mismatched identity, shape or nonmatching active IDs before state mutation. It advances fields once, uses the validated eyes with that tick's odor/taste, updates each brain and body in the existing order, and yields a record with the consumed retinal values and original eye poses.

A duplicate commit or future/wrong-generation batch cannot cause a second step. Cancellation invalidates pending work immediately; late GPU completion is discarded. A renderer error or context loss ends the attempt through the existing recoverable failure UI. Do not feed black frames as a fallback, reuse another fly's eyes, retry partially advanced native state, or spin until acquisition succeeds. Starting a new attempt creates valid state after cleanup.

Acquisition is driven by simulation ticks, never `requestAnimationFrame`, playback speed, selection or elapsed wall time. Keep 10 Hz fixed after the profile freezes. Any future held-frame cadence is a separate explicit reslice, including sample-age records; it is not an adaptive runtime performance trick.

The preferred backend is OffscreenCanvas/WebGL2 in the existing attempt worker, awaiting the actual renderer's asynchronous readback. Slice 02 must test the real asset loading path and supported browser. It must not introduce a second worker merely to forward eye messages. If this architecture fails the bounded feasibility gates, revise the backend decision before production work; a main-thread service or CPU sensor is not an unreviewed fallback.

## Retinal-to-neural mapping

Keep the audited Tm2 population for a brightness branch and retain graph bytes. Color requires a separately audited set of retained color-related cells and a declared channel-response model from slice 04. The audited model uses Tm20 for a modeled blue branch and excludes Tm5 cells whose source columns are missing; these type names do not imply RGB receptor identities. A type name alone cannot justify spectral weights or receptor subtype assignment. No R1–R8 fabrication, graph expansion, new training or movement-decoder change. Use full-source family bounds, not the selected subset's bounds, to register both annotated hex coordinates onto the declared two-dimensional retinal layout. Axis orientation, mirroring, field coverage and receptive-field width must be labeled **modeled**. Never flip an axis to obtain preferred behavior.

Slice 05 delegates the numerical spatial registration to a reproducible geometry-only audit: start from the axial-coordinate embedding `(h1 + h2/2, sqrt(3)*h2/2)`, centre/scale each full-source eye into the frozen lattice, and freeze orientation against slice-01/03 landmark conventions. Produce sparse local nonnegative taps (nearest containing sample triangle, at most three taps before normalization). Mark samples without retained target coverage in the audit; do not stretch the selected neurons to hide holes or label all retinal samples as represented neural cells.

Normalize each supported sample column by its sum, then use one global scale so the largest neuron row sum is at most one. Equal-area basis samples within represented support then have equal aggregate weight, and each cell remains bounded by the existing gain. A claimed bilateral comparison must use matched supported sample areas and report total input per eye; if full-eye support differs, do not claim equal full-field dose. The 128/238 population imbalance remains a fact, not something to repair with invented cells.

Quantization happens **before** neural consumption. The brightness branch may retain `q/(q+0.5)` after deriving its declared signal from RGB8. The chromatic branch must preserve independent color information using the exact spectral approximation frozen by slice 04; summing all channels to one brightness signal is not acceptance. Freeze channel transforms, signs, any baseline currents, supported stimulus gamut and family allocations before neural testing. The final external current per mapped cell must stay within `[0, gain]`, with `gain ≤ 3`; any signed chromatic feature therefore needs an explicitly frozen rectification/baseline model. Bound the combined brightness and chromatic contributions; adding a pathway must not multiply the current budget silently. Characterize both branches separately and together. Reuse campaign gain three without tuning to improve escapes. No rule may encode that a named color means food, exit, attraction or danger.

Rendered RGB is a human-display representation, not a spectrum. Real flies have UV-sensitive as well as blue/green-sensitive pathways. No UV measurement can be reconstructed from ordinary RGB textures; this feature has no authored UV channel and must not invent one from blue or object identity. The final panels are color visualizations of the sampled rendered scene, not a claim to depict a fly's subjective color experience. Color-sensitive **modeled downstream response** is required; biological color fidelity and particular color preferences are not. See [color research](research.md#color-requirement-and-primary-evidence).

Map metadata binds graph hash, annotation hash, profile/layout hash, channel-transform hash, cell families, sparse spatial/channel taps, support masks and registration description. Runtime loads it once. Motor-readout targets remain forbidden. A missing/invalid map with vision enabled is a handled initialization failure, never silently zero current.

## Replay and old versions

Advance the development record schema to **6**, publishing only the final layout at campaign cutover. Native `RecordLayout` owns dimensions, channel order and strides. Replace the sixteen old directional brightness/blocked fields with the required full pre-neural eye pose fields and a contiguous uint8 eye buffer. Do not put pixels in f64 arrays, JSON, base64 or encoded movies. Existing planar input position/heading fields can be reused; record the missing pre-neural height and quaternion.

The uint8 buffer is the exact batch consumed by the brain, retained through ordinary native packing, transfer and `FrameArchive` ownership. Every sampled active tick has both eyes. Input is absent only when the fly was already terminal at the beginning of the tick. A fly that consumes eyes and becomes terminal during commit retains that transition tick's real samples. Zero bytes in unused storage do not mean a dark stimulus. Each fly’s right-column detail view directly presents paired “Left eye” and “Right eye” color previews, similar to the reference demo, above the existing brain/traces block. No extra modal or diagnostic toggle is required. The UI never rerenders historical eyes or interpolates between sensor frames. It displays the latest recorded tick at or before the playback cursor and labels its acquisition time. Use the sensory-presence flag, not the post-step outcome, to decide availability: display real samples on the terminal-transition tick and unavailable on subsequent unsampled ticks. Selecting a different fly selects its recorded samples, never creates capture work.

At the **public archive/chunk decoding boundary**, check schema before constructing version-specific typed views. An old schema returns a structured unsupported-record outcome, rendered as: “This recording uses an older format. Start a new attempt to view the fly's eyes.” Keep the app responsive with a way to return to setup/start again. Do not add a schema-5 compatibility decoder or migration. Treat truncated/corrupt records as handled invalid-record errors, not unsupported versions. Existing stale-generation transport messages retain their ordinary ignore behavior.

Test a real frozen schema-5 fixture, current schema-6 fixtures, truncated headers, and failure after a previously valid view. None may produce an uncaught exception, blank app or modification of progress/arrangements. Do not build an import screen merely to expose this test.

## Resource budgets

These are release targets to measure, not observations. Record hardware, OS, browser/version, power state, build/profile/scene identities and warm/cold conditions. Use the development Mac with hardware-accelerated Chromium as the acceptance machine; perform a WebGL2 capability/error-path smoke on Safari. The report must state what was actually tested rather than imply support for unmeasured devices.

- At 128×128, sixteen flies need 32 views and 524,288 rendered pixels per tick. Batch them into one bounded atlas/readback where the platform permits; reserve storage for at most sixteen flies, not one renderer per eye. Readback staging is at most two complete atlases; no frame queue can grow with run duration.
- Canonical retinal history at 721 RGB8 samples/eye costs 415,296,000 bytes over 16×6000 ticks, before pose/metadata. Keep the **combined archive at or below 512 MiB**, including existing motion, events, neural values and layout/chunk overhead. Update native admission arithmetic before allocations. Do not rely on average compression or silently evict old eyes.
- Report graph/brain WASM, producer scratch, in-flight chunks, consumer archive, GPU resources and JS buffers separately without double-counting transferred buffers. Transient capture allocations must remain constant with attempt duration and plateau over ten retries.
- Target warm 16-fly acquisition p95 **≤20 ms per complete tick batch**, including scene submission, GPU wait, readback, pooling and transfer into WASM. Report median, p95 and worst sample; do not time submission alone.
- Full production must finish within the simulated duration on the acceptance machine, with zero playback underruns and the frame-time bound below. Retain paired old-vision and capture-only measurements as diagnostic evidence, including negative results and workload differences; neither replaces the full UI run. The initial 1.20× relative target belonged to the rejected 32×32/61-sample profile and is superseded under the user’s explicit budget delegation. The [budget reconciliation](assets/11/baseline-control/measurement/README.md) preserves its failed measurement and the reason for this change.
- Target main-thread frame p95 **≤33 ms** while viewing playback on the acceptance machine, cancellation acknowledgement p95 **≤100 ms**, and return to setup p95 **≤200 ms** on warm retries. Capture failure must settle within **5 seconds** of a lost/unresponsive acquisition, after which the existing error UI offers restart; this timeout is failure handling, not a polling loop.
- Final browser gates: both full 6000-tick campaign rounds, sixteen flies, pause/rewind/selection, zero replay underruns after playback starts in the tested run, and no accumulating capture work. Test 20-fly lab admission separately; reject unsupported sensor workloads before starting rather than crashing. The campaign requirement is sixteen; do not weaken the existing nonvisual lab paths.

The user rejected the initial coarse profiles. Slice 02 compared 64/128/256-pixel capture with 217/469/721-cell regular hex layouts and selected 128×128 / 721 cells, retaining all three RGB8 channels. The user explicitly delegates practical memory-budget decisions; 512 MiB is the present engineering cap, not a user-imposed limit. Revisit it from measured total memory if necessary, without excessive multi-gigabyte allocation. Test acquisition resolution and sample layout one variable at a time; color-channel retention is fixed. The discarded grayscale candidate is not eligible. Keep 10 Hz. Choose the smallest profile whose asymmetric landmarks, doorway gaps and lateral movement remain readable and whose memory and latency gates pass. Record the comparison and update this file, every dependent slice and map identity before integration. If no candidate passes, reslice; do not silently drop to 1-D vision, 5 Hz, selected-fly-only sensing or undocumented resource changes.

## Native verification boundary

GPU image generation is browser-dependent; cross-device bitwise render determinism is not promised. The recorded quantized batches are the oracle. Export them from the browser fixture runner with the complete request/profile/scene identity, then feed the **same bytes** into native and WASM tick drivers. Verify tick/body/record correspondence and use the project's established numeric tolerances for neural dynamics; any drift that changes an outcome must be investigated.

Native probes needing live visual input must request a supplied batch source or fail clearly when one is absent. They must never retain the old light-bin sampler behind the same visual mode. This feature does not include a second native optical renderer. Optical comparison across browsers uses a declared tolerance and landmark behavior; replay within an archive uses exact byte equality.
