# Fixed eye attachment

The generated [eye rig](../../../../packages/game-renderer/src/retina-eye-rig.ts) binds the reference camera axes to the authored fly's neutral eye centres. Position comes from the real, skinned GLB; orientation comes from the source-frozen optical profile. These are different authorities: the asset establishes where its eyes are, but does not establish an optical field of view or a biological camera direction.

The exporter uses the production `loadFlyModel`/`GLTFLoader`, updates world and skeleton matrices, then measures each eye with Three's precise skinned `Box3`. Reading only GLB node translations or raw accessor bounds misses skinning and yields the wrong coordinates. The neutral scene's support pivot is the native body origin. Native GLB units are already metres; no multiplication by the presentation scale, animation phase or camera zoom is involved. See [native asset geometry](../../../../assets/fly/README.md) for the unit authority.

Physical left is body `+X`, with body `+Z` forward and `+Y` up. The GLB suffixes are viewer-relative: `EyeR021` occupies physical left and `EyeL021` physical right. This matches the reference's source `+Y` left through the proper `[sourceY, sourceZ, sourceX]` basis conversion. At native heading zero, body `+X` points toward world `−Z`, while forward points toward world `+X`. The exporter checks both measured centres and optical directions against those signs; changing labels to follow suffixes would reverse the experiment.

The fixed orientations preserve the rounded source angles through the [reference profile](../01/reference-profile.json), with no extra pitch or fitted rotation. Quaternion storage is `(x,y,z,w)`, mapping camera-local coordinates into the native body; camera forward is local `−Z`, up is `+Y`. Acquisition must apply the complete pre-neural native pose: `worldOrigin = bodyPosition + bodyQuaternion × positionMetres`, and `worldCameraQuaternion = bodyQuaternion × cameraToBodyQuaternion`. The vertical component is relative to the native support pivot, not a second body height to add independently. Articulation and animation do not move this fixed rig.

## Reproduce and verify

From the repository root, using the repository's pinned Bun dependencies:

```sh
bun install --frozen-lockfile
bun specs/retinal-vision/assets/03/export-eye-rig.mjs
bun specs/retinal-vision/assets/03/export-eye-rig.mjs --check
bun test packages/game-renderer/src/retina-eye-rig.test.ts
bun run test:renderer
```

The generated module is recursively frozen at runtime and readonly in TypeScript. It carries exact GLB and reference-profile SHA-256 identities; the rig hash covers those identities, frame and all eye values in exporter insertion order using `JSON.stringify`. The [provenance artifact](eye-rig-provenance.json) records skinned bounds and the Three revision. `--check` recomputes the measurements and rejects stale generated bytes instead of silently accepting a changed asset. The exporter uses the renderer's installed Three dependency; it adds no package dependency.
