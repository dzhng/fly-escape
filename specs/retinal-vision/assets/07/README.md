# Exact retinal records — preparation evidence

The archive owns one transferred buffer per numeric stream, including RGB8. Full-population slots keep tick/eye addressing independent of which fly is selected. Presence is independent of byte values: black input remains present, the terminal-transition tick retains its consumed input, and subsequent inactive slots are absent. Native requests remain the authority for input transforms; the record also checks agreement with the motion start. The wire contract lives in `crates/sim/src/record.rs`, its retinal invariant helper, and the public `FrameArchive` decoder.

The retained header binds the map, optical profile and scene. Full layout metadata includes the immutable profile, rig and color identities. A stale attempt cannot alter a current archive; a malformed current chunk fails before ownership transfer or history mutation. Old-format records are rejected deliberately, with a readable message and the existing return-to-setup action. There is no migration or second archive.

## Verified scope

The native-produced [schema-6 fixture](schema-6.json) is deliberately synthetic, including its identities. [Schema 5](schema-5.json) was generated by the native fixture before this change and serves only as a rejection input. Cross-language tests compare exact RGB bytes and poses through arbitrary seek order and repeated selection; mutating returned bytes cannot mutate the archive. Flipping one packed byte made the fixture test fail; restoring the packer made it pass.

[The browser/WASM probe](retina-record-wasm.json) uses the real graph and reviewed map with controlled RGB. The actual WASM session consumes those bytes, emits two chunks, and the public JavaScript archive decodes and seeks all 12 ticks exactly. This verifies the browser transfer boundary, **not physical camera acquisition**. Physical capture through the production worker and full campaign resource gates remain open for the integrating task.

[Browser failure evidence](browser/report.json) exercises old and future schemas, truncated and corrupt metadata, and payload corruption after accepted production data. Every case returns to usable setup without page errors or changes to seeded stars and arrangements. The standard interruption is a visual reference. [Visual assessment](visual-review.md) covers the message and recovery control; it makes no renderer-quality claim.

## Resource boundary

[The full retained-history stress report](retina-record-memory.json) checks every eye byte for sixteen flies through 6000 ticks. It deliberately adds sixteen neural groups, six motion points and eight events to every fly/tick. These controlled records are a packing stress case, not a biological or campaign benchmark.

The archive target is 512 MiB. Fixed admission uses the production worker's maximum chunk size and includes all RGB, fixed records, bounded event storage, envelope allowance and metadata. The envelope allowance covers long escaped identities as well as chunk ownership. Smaller chunks are allowed by the public API but consume the same cumulative quota; they do not enlarge it. Native preflight rejects overflow before packed-buffer allocation, and the consumer rejects it before retaining buffers. No eviction or compression hides an overflow.

Arbitrary maximum-length motion traces at every tick do not fit this target. Variable motion therefore has an explicit remaining quota, and a production overflow is a visible failure. The six-point stress result is not a promise that every possible motion history fits. Process RSS, WASM high-water memory, transient seek copies, worker staging and archive ownership are separate quantities; the reports show these independently rather than treating the archive target as a whole-process cap.

## Reproduce

Prepare the real browser graph assets and build WASM, then run the web dev server. With its address in `BRAIN_URL`, run `bun run test:retina-record`. The command runs the native-produced consumer fixtures, full retained-memory probe, controlled browser/WASM worker and browser failure consumer. It requires a local Chrome installation. Fixture regeneration is `cargo run -q -p sim --example record_fixture -- --retinal`; the frozen schema-5 fixture must not be regenerated with the current producer.
