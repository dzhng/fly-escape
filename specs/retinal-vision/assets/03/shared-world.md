# Shared world construction

`WorldScene` is the shared composition and disposal owner for the house, room attachments and placement artwork. The presentation view and a future sensory renderer can each own a separate instance built by the same loaders and authoring. Loading separate resource sets keeps cutaway material changes and disposal local to one world; there is no shared mutable scene, asset cache or reference-counting system.

[WorldScene](../../../../packages/game-renderer/src/world-scene.ts) owns its physical groups and the shared readiness gate. `HouseGeometry` still owns wall joins, floor fitting and authored furniture assembly. `PlacementModels` still owns placement transforms and catalog scaling. `RoomDetails` owns wall-attachment fitting and its source resources. Asset URLs remain in the existing house/detail catalogs and tool registry. Resolved placements and fixed objects use these owners; contact/support envelopes do not substitute for artwork.

The presentation policy preserves existing wall/furniture cutaways, doorway opacity, room-detail camera hiding, ghosts and lighting. `WorldView` retains camera/navigation, fly animation and display scaling, grass, diagnostic markers, trails, finish cues and presentation light rules. Its house replacement still refreshes bounds/navigation, while pure asset installation uses the actual shared owners. The shared asset gate refreshes view bounds after loading completes.

The physical policy constructs only full wall instances and preserves original doorway materials. Camera visibility updates cannot hide those walls or room attachments, and placement ghosts are ignored. No fly bodies, grass, rings, field/contact overlays or finish cues enter this composition. Static placement asset validation already excludes animation, so this pass does not invent a separate animated fan phase. The scene has no automatic lighting: callers supply explicit point, directional or hemisphere light descriptors in world metres.

## Lighting remains an integration decision

Presentation lighting numbers and source rules are unchanged. In particular, the game still points sunlight from exit metadata and its `ExitGlow` still carries a real point light. Neither path is part of the physical scene. Physical room-detail construction also omits the presentation's automatic sconce lights, so a future caller must supply explicit authored descriptors rather than accidentally inheriting a partial light model.

## Verification and repeatability

All 89 renderer tests and both asset tests pass, as does whole-repository TypeScript checking. Both web and asset-lab production builds pass. The isolated worktree used the parent's already-generated WASM artifacts in its ignored build folder; no product dependency or native/WASM source changed. The physical test uses real authored GLBs and checks opaque geometry, camera invariance, placement transforms, independent disposal, absence of implicit light and rejection of ghosts. It deliberately fails when the physical house is constructed with presentation cutaways, then returns to green after restoration. Failed/stale placement loads are also checked through installed artwork; the gate waits for all started categories before returning a failure.

A bounded production browser comparison covered both campaign setup levels, each in overview and after the same right-button orbit. It did not run an attempt, full campaign or performance benchmark. Both origins used fresh storage, the same earned-star fixture, 1440×1000 viewport, DPR 1 and `performance.now() = 12345` to freeze presentation animation. The baseline was the parent-provided static production build; [served build identities](world-builds.json) distinguish its entry script from the candidate's. [Browser observations](world-browser-check.json) report no page errors.

All four candidate PNGs are byte-identical to their corresponding references: zero changed pixels, zero RGB delta and zero grayscale distance. [Comparison metrics](world-comparison.json) retain luminance and edge energy as evidence that these are populated frames. The `world-reference/` and `world-candidate/` folders contain full frames; `world-comparison/` contains enlarged interior crops and 8× amplified difference images.
